## 1. 前提（検証済み・再議論しない）

- **収益エンジン = バイラル・シェアループ ＋ SEO（検索流入）**
- **送客の主役は X（旧Twitter）＋ TikTok**。Instagram は認知・ブランディング／キャラ資産の見せ場
- **堀はキャラIPの一貫した可愛さ**。機能の新しさ（192タイプ/レア/ランキング）は"燃料"であって堀ではない
- **広告は当面ゼロ**。実測が出てから勝ちリールのブーストにだけ少額投下
- 広告アービトラージ（広告→サイト→AdSense）は**1PVあたり約50倍の赤字**で原理的に不成立
- ボトルネックは**入口（外部→サイト）**。サイト内CVR（着地→診断開始 40〜60%）は既に強い

**必要規模の目安**（RPM ¥280・2.5PV/session）
| 月間収益 | 必要PV/月 | 目安PV/日 |
|---|---|---|
| ¥30,000 | 約107,000 | 約3,600 |
| ¥100,000 | 約357,000 | 約12,000 |
| ¥300,000 | 約1,070,000 | 約36,000 |

→ RPMが弱気（¥150）ならほぼ2倍。**「1本のバズ」ではなく「バズが再生産される仕組み」が要る。**

## 2. コードを調べて分かった現状（事実）

**すでに強い土台がある**
- タイプ別ページ **209枚**（MBTI×干支192 ＋ MBTI16 ＋ ハブ）。各ページ約4,000字、固有の全国偏差値・干支解説・相性・内部リンク付き
- ロングテール設計済みのtitle/description（例:「寅年生まれの…INTJ…性格・恋愛・相性・偏差値」）
- `sitemap.xml` / `robots.txt` 完備
- 結果のシェア画像生成（Canvas 1080×1920）実装済み
- GA4 ＋ Metaピクセル設置済み（`ev()`で全イベント送信）

**新方針に対する致命的な穴（＝伸びしろ）**
1. **タイプ別OGPが存在しない** — 209ページ全部が共通 `ogp.png` を参照。X/LINEでシェアしても**全員同じカード**。バイラルの一番おいしい所（シェアされた瞬間のクリック率）を捨てている
2. **構造化データ（JSON-LD）がゼロ** — 検索での見え方・リッチリザルトの機会損失
3. シェア動線が「画像保存」中心で、**画像からサイトへ戻る導線が弱い**

> つまり **SEOもシェアループも「土台はあるのに増幅装置が付いていない」**状態。ゼロから作る話ではない。

## 4. #1 の設計（サンプル生成済み）

- サイズ **1200×630**（OGP標準／X summary_large_image）
- 構成: キャラ ／ タイプ名 ／ MBTI＋干支バッジ ／ **自慢できる偏差値** ／ ブランド＋無料訴求
- **ブランドは固定**（ゆめかわピンク）＝ キャラIPの一貫性が堀なので崩さない
- `ranking.js` の **tier設計（不安照ケア原則）を尊重**し、全国順位を明示するのは `top`/`high` のみ。`mid` はキャッチで見せる
- キャラ色が薄い場合（例: INTPのシルバー）は**自動で暗くして可読性を確保**
- 軸は7種に自然分散（天才度38・金運30・モテ27・一途25・ヤンデレ25・コミュ24・メンタル23）
  → **人によってカードが違う＝シェアされる理由になる**
- tier分布: top 49 / high 114 / mid 29（**163/192 が順位を出せる＝自慢素材になる**）

**生成方法**
```bash
node dump_type_data.js           # data.js/ranking.js から _data.json を生成
python make_type_ogp.py --sample # サンプル4枚（デザイン確認用）
python make_type_ogp.py          # 全208枚 -> assets/og/types/*.jpg (約16.6MB)
node make_type_pages.js          # 209ページを再生成(og:imageが個別画像を指す)
```

**実装結果（完了）**
- 208枚を **JPEG q90** で出力（PNGだと32.5MB→16.6MBに半減。見た目の劣化なし）
- `make_type_pages.js` の `head()` に `ogImage` 引数を追加し、**再生成しても崩れない**ように統合
- `og:image:width/height/alt` も追加（クロールとアクセシビリティのため）
- 検証: 参照418件すべて実在（**欠損0**）、**ユニークOGP 209種類**（旧1種類）
- ハブページ（`types/`）のみ共通OGPのまま（一覧ページのため意図的）
